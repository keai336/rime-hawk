# 最佳实践详解：盯住第一个不合意的字

这份文档展开 README 中的实践要点。示例来自调试日志里的典型路径，重点不是记住某个指令，而是形成稳定的纠偏顺序。

## 核心策略

Hawk 的高效用法不是一次性把整句调到完全正确，而是从左到右处理：

1. 先看候选里第一个不合意的字或词段。
2. 用这个位置对应字的辅码去筛选、截断或修音。
3. 确认已经正确的前缀。
4. 剩余拼音会继续留在候选区，再重复同样的动作。

断句和分心都应该是低频纠偏操作。日常输入优先使用普通辅码过滤；只有当候选被错误组词、二字词需要拆开判断，或音节确实打错时，再使用这些高级能力。

## 逐段筛选

例如想得到「魏馨怡」，输入串已经在候选区，但首段不合意时，可以逐段盯着第一个不对的字修：

```text
wwxbyi;xa   -> 魏...
wwxbyi;g    -> 魏馨...
wwxbyi;h    -> 魏馨怡
```

要点是不要急着处理后面的字。先把最左边不对的字筛准，确认后再处理下一个。调试日志里也能看到，前缀被确认后，剩余输入会继续保留下来参与后续筛选。

## 二字词分心

二字词的两个字都知道辅码时，可以直接用两位辅码：

```text
xbyi;hj,    -> 心...
xbyi;jb     -> 心仪
```

如果第一位辅码已经让首字正确，第二位辅码会继续作用到下一轮。这适合处理「第一个字对了，第二个字还不对」的情况。

分心不是默认输入路径。它适合明确知道两个字的辅码，并且普通候选无法自然给出目标词时使用。

## 长句断句

长句里某个词被错误组词时，仍然先看第一个不合意的位置：

```text
wodewuliiglewodebdbi;du;  -> 我的
wodewuliiglewodebdbi;du   -> 我的无力成了我的败笔
```

第一步先截出已经正确的「我的」，剩余部分继续用同一个辅码定位「无」。断句的价值在于把已经正确的前缀固定下来，避免为了后半句反复扰动前半句。

## 修音

如果第一个不合意的字来自音节打错，先用该错字的辅码定位，再用 `s` 改音：

```text
zvjxgruz;wk;     -> 最佳
zvjxgruz;wk;sge  -> 最佳歌手
```

这里 `wk` 用来定位错误音节附近的断点，`sge` 把错打的音节改成 `ge` 后重新组词。

## 推荐顺序

1. 普通辅码过滤。
2. 确认正确前缀，继续处理剩余拼音。
3. 二字词确实需要拆开判断时，再用分心。
4. 长句被错误组词时，再用断句。
5. 音节本身打错时，再用修音。
